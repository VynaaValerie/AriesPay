## 1. Overview

AriesPay is an enterprise payment gateway providing white-label QRIS and multi-channel payment processing for web and mobile applications.

Key capabilities:
- Realtime National QRIS (BCA, Mandiri, BRI, BNI, GoPay, OVO, DANA, ShopeePay, LinkAja).
- Virtual Accounts and Retail channels.
- Double-entry ledger with integer rupiah precision (zero floating-point precision loss).
- Automated 24-hour holding period for incoming transactions with Asia/Jakarta (WIB) time stamping.
- Real-time webhook callbacks secured by cryptographic signatures.

---

## 2. Authentication & Security

All API endpoints require authentication using credentials obtained from the AriesPay Merchant Dashboard.

### Authentication Headers

Include the following HTTP headers in every request:

```http
Content-Type: application/json
x-merchant-id: YOUR_MERCHANT_ID
x-secret-key: YOUR_SECRET_KEY
```

### Signature-Based Authentication (Optional Alternative)

For systems that prefer payload signatures over raw secret headers, endpoints accept a `signature` parameter:

```
signature = md5(merchant_id + ":" + secret_key + ":" + unique_param)
```

Where `unique_param` is either `reff_id` (for orders) or `nominal` (for withdrawals).

## 3. Settlement & Balance Holding Policy (24-Hour WIB)

AriesPay enforces an automated **24-Hour Settlement Holding Period (T+1)** based on **Asia/Jakarta (WIB, UTC+7)** time:

1. **Transaction Inflow**: When a payment is completed, the net amount is credited to `settlementBalance` (Saldo Ditahan), not to `availableBalance`.
2. **Holding Duration**: The balance is held for exactly 24 hours from the payment timestamp (`paidAt`).
3. **Maturity & Release**: Once 24 hours have elapsed, funds atomically transfer from `settlementBalance` to `availableBalance` (Saldo Tersedia).
4. **Withdrawal Eligibility**: Only funds in `availableBalance` can be withdrawn to bank accounts or e-wallets. Attempts to withdraw funds still in the holding period will be rejected with an informative notice.

## 4. API Endpoints

### 4.1 Create Payment Order (POST /api/v1/order)

Creates a new payment transaction and returns payment instructions (QRIS string, checkout URL, or virtual account).

- **Endpoint**: `POST https://ariespay.web.id/api/v1/order`
- **Headers**:
  - `Content-Type: application/json`
  - `x-merchant-id: AP_M267BF3849F`
  - `x-secret-key: YOUR_SECRET_KEY`

#### Request Parameters

| Parameter | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `reff_id` | String | Yes | Unique invoice or order ID generated by merchant (max 64 chars). |
| `amount` | Integer | Yes | Total transaction amount in Rupiah (min. 1000). |
| `kode_channel` | String | No | Payment channel: `QRIS`, `BCA`, `BRI`, `BNI`, `MANDIRI`, `OVO`. Default: `QRIS`. |
| `customer_name` | String | No | Customer full name. Default: `Pelanggan`. |
| `customer_email` | String | No | Customer email address for receipts. |
| `customer_phone` | String | No | Customer mobile phone number (08xxx). |
| `redirect_url` | String | No | URL to redirect customer upon payment completion. |
| `expired_ts` | Integer | No | Unix timestamp for invoice expiration (default 30 mins). |

#### Request Example (cURL)

```bash
curl -X POST "https://ariespay.web.id/api/v1/order" \
  -H "Content-Type: application/json" \
  -H "x-merchant-id: AP_M267BF3849F" \
  -H "x-secret-key: sk_live_your_secret_key" \
  -d '{
    "reff_id": "INV-20261015-001",
    "amount": 50000,
    "customer_name": "Budi Santoso",
    "customer_email": "budi@example.com",
    "customer_phone": "081234567890",
    "kode_channel": "QRIS"
  }'
```

### 4.4 Withdrawal / Payout Request (POST /api/v1/tarik-saldo)

Submits a payout request to a designated bank account or e-wallet. Only matured funds from `saldo_tersedia` can be withdrawn.

- **Endpoint**: `POST https://ariespay.web.id/api/v1/tarik-saldo`
- **Headers**:
  - `Content-Type: application/json`
  - `x-merchant-id: AP_M267BF3849F`
  - `x-secret-key: sk_live_your_secret_key`

#### Request Parameters

| Parameter | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `nominal` | Integer | Yes | Amount in Rupiah (min. 25.000 weekdays, min. 200.000 weekends). |
| `bank_code` | String | No | Target bank/e-wallet (`BCA`, `MANDIRI`, `BRI`, `BNI`, `DANA`, `GOPAY`, `OVO`, `SHOPEEPAY`, `LINKAJA`). Defaults to registered bank. |
| `account_number`| String | No | Target bank account number or e-wallet mobile number. |
| `account_name` | String | No | Account holder name as registered at the bank. |

### 5.2 Signature Verification Formula

Compute the MD5 hash on your server and compare it with the `signature` field in the payload:

```text
signature = md5(merchant_id + ":" + secret_key + ":" + reff_id)
```

Example in Node.js:
```javascript
const crypto = require('crypto');

function verifyWebhook(body, secretKey) {
  const expected = crypto
    .createHash('md5')
    .update(`${body.data.merchant_id}:${secretKey}:${body.reff_id}`)
    .digest('hex');

  return expected.toLowerCase() === (body.signature || '').toLowerCase();
}
```

### 5.3 Expected Merchant Server Response

Your webhook endpoint **must** return an HTTP 200 response with JSON:

```json
{ "status": true }
```

If your server returns any HTTP status other than 200 or times out after 10 seconds, AriesPay will retry delivery using exponential backoff.

### 5.4 Webhook Implementation Examples

#### Node.js / Express Example

```javascript
const express = require('express');
const crypto = require('crypto');
const app = express();

app.use(express.json());

const MERCHANT_ID = 'AP_M267BF3849F';
const SECRET_KEY = process.env.ARIESPAY_SECRET_KEY;

app.post('/api/webhook/ariespay', (req, res) => {
  const { status, reff_id, signature, data } = req.body;

  // 1. Verify Signature
  const calculatedSig = crypto
    .createHash('md5')
    .update(`${data.merchant_id}:${SECRET_KEY}:${reff_id}`)
    .digest('hex');

  if (calculatedSig.toLowerCase() !== (signature || '').toLowerCase()) {
    console.error('Invalid signature received');
    return res.status(400).json({ error: 'Invalid signature' });
  }

  // 2. Process Business Logic
  if (status === 'Success') {
    console.log(`Payment confirmed for Order #${reff_id}: Rp ${data.total_dibayar}`);
    // Update order status in your database to 'PAID'
  }

  // 3. Mandatory HTTP 200 Response
  return res.status(200).json({ status: true });
});

app.listen(3000, () => console.log('Webhook server running on port 3000'));
```

#### PHP Native Example

## 6. HTTP Status Codes & Error Handling

| Code | Status | Meaning & Troubleshooting |
| :--- | :--- | :--- |
| `200` | OK | Request succeeded. |
| `400` | Bad Request | Missing required parameters, nominal below minimum, or signature mismatch. |
| `401` | Unauthorized | Missing or invalid `x-merchant-id` or `x-secret-key`. |
| `404` | Not Found | Transaction with specified `reff_id` or `trx_id` was not found. |
| `429` | Too Many Requests | Rate limit exceeded. Back off and retry. |
| `500` | Internal Server Error | Gateway internal error. Retry with idempotency key or contact support. |
